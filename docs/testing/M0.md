# M0 manual test checklist: scaffold

**What M0 delivers:** a `clip-atlas.dll` that OBS loads and that logs a line. It has no features yet. These steps confirm that the CI build installs and loads on a real Windows machine with OBS 31.

**You need:**
- Windows 10 or 11, 64-bit
- OBS Studio 31.x. If you only have 32.x, test with it and write the version in the results.
- The CI artifact `clip-atlas-0.1.0-windows-x64-<commit>.zip`. It's linked from the pull request description; download it from the Artifacts section of that Actions run.

Write **Pass** or **Fail** in each Result cell, and add a note for anything unexpected. If a step fails, copy the relevant log lines into the Notes column.

## Steps

| # | Step | Expected result | Result | Notes |
|---|---|---|---|---|
| 1 | Close OBS completely, including from the system tray. | OBS is not running. | | |
| 2 | Extract the artifact zip. Inside is another zip, `clip-atlas-0.1.0-windows-x64.zip`; extract that too. | You have a folder `clip-atlas` that contains `bin\64bit\clip-atlas.dll`, `bin\64bit\clip-atlas.pdb` and `data\locale\en-US.ini`. (If the layout differs, find the folder that contains `bin\64bit\clip-atlas.dll`, and note the layout here.) | | |
| 3 | Copy the `clip-atlas` folder into `C:\ProgramData\obs-studio\plugins\`. Create the `plugins` folder if it doesn't exist. Windows asks for administrator permission. | `C:\ProgramData\obs-studio\plugins\clip-atlas\bin\64bit\clip-atlas.dll` exists. | | |
| 4 | Start OBS. | OBS starts normally, with no error dialog about a plugin. | | |
| 5 | Open **Help → Log Files → View Current Log**. Search (Ctrl+F) for `clip-atlas`. | There is a line containing `[clip-atlas] loaded v0.1.0`. | | |
| 6 | In the same log, look at the lines just before and after it, and search for `Failed to load` and `clip-atlas.dll`. | No line says `clip-atlas.dll` failed to load. | | |
| 7 | Open **Help → About** and note the OBS version. | Just record it, for example 31.0.2. | | |
| 8 | Use OBS briefly: switch scenes, start and stop the Replay Buffer if you use it. | Nothing behaves differently from before. M0 has no features, so nothing should be sorted or moved. | | |
| 9 | Close OBS. Start it again, then open **Help → Log Files → Show Log Files** and open the log file from the previous session (the second-newest). Search for `clip-atlas`. | The previous session's log contains `[clip-atlas] unloaded` near the end. | | |
| 10 | Uninstall: close OBS, delete `C:\ProgramData\obs-studio\plugins\clip-atlas`, start OBS, and view the current log. | OBS starts normally, and the log has no `clip-atlas` lines. | | |
