# M1 manual test checklist: replay sorting and the Replay Buffer

**What M1 delivers:** Clip Atlas does what the Python script did, natively:
- It notices when a game is captured.
- It starts and stops the Replay Buffer for you.
- It sorts every saved replay into `<Clips folder>\<Game>\<YYYY-MM>\`.

**You need:**
- Windows 10 or 11, OBS Studio 31.x, and one game you can start and quit quickly.
- The CI artifact `clip-atlas-…-windows-x64-<commit>.zip` from the M1 pull request.
- The **Replay Buffer turned on**: Settings → Output → Replay Buffer → "Enable Replay Buffer".

Write **Pass** or **Fail** in each Result cell. If something fails, open **Help → Log Files → View Current Log**, search for `clip-atlas`, and paste the nearby lines into Notes.

## Before you start

1. If the old Python script is loaded (**Tools → Scripts**), select `rb_event_driven.py` and click **−** to remove it. Running both would make them fight over the same clip.
2. Close OBS. Delete `C:\ProgramData\obs-studio\plugins\clip-atlas` if it is there from M0. Then install the new `clip-atlas` folder the same way as in M0: unzip twice and copy it into `C:\ProgramData\obs-studio\plugins\`.
3. Make sure your scene has a **Game Capture** source (any capture mode).

## Steps

| # | Step | Expected result | Result | Notes |
|---|---|---|---|---|
| 1 | Start OBS. Open **Help → Log Files → View Current Log** and search for `clip-atlas`. | `[clip-atlas] loaded v0.1.0` and a line naming the clips folder. No errors. | | |
| 2 | Open **Tools → Clip Atlas Settings…**. | A dialog with a **Clips** section (clips folder with Browse…, monthly folders, unsorted folder name) and a **Replay Buffer** section (start, stop, grace period 10 s). It matches your OBS theme. | | |
| 3 | Leave the clips folder empty and click **OK**. | The dialog closes. Grey placeholder text in the field showed your OBS recording folder. | | |
| 4 | With the Replay Buffer **stopped**, start your game, with the Game Capture source in the current scene. | Within a few seconds the Replay Buffer **starts by itself**, and the button shows it is active. | | |
| 5 | Press your **Save Replay** hotkey (or click the save button). Wait about 5 seconds. | In your recording folder, the clip is **not** at the top level. It is in `<recording folder>\<Game name>\<this month, e.g. 2026-10>\`. Write down the game folder name. | | |
| 6 | Save two more replays quickly, one after another. | Both arrive in the same game folder. Nothing is lost or overwritten. | | |
| 7 | Quit the game. Within 10 seconds, save one more replay. | That clip still goes into the **game's** folder (10 s grace period). | | |
| 8 | Wait about 15 seconds after quitting the game. | The Replay Buffer **stops by itself**. | | |
| 9 | Start the game again. Within 10 seconds of quitting it, start it once more. | The buffer stays running throughout: reopening within the grace period cancels the stop. | | |
| 10 | With no game running, start the Replay Buffer **yourself** and save a replay. | The clip goes to `<recording folder>\Unsorted\<month>\`. | | |
| 11 | Leave the buffer you started yourself running, start the game, then quit it and wait 20 s. | The buffer **keeps running**: Clip Atlas never stops a buffer it didn't start. | | |
| 12 | Stop the buffer yourself while the game is running. | Clip Atlas does **not** restart it while that game keeps running. | | |
| 13 | (If you use **auto-remux**: Settings → Advanced → Recording → "Automatically remux to mp4", with the recording format set to mkv.) Save a replay during a game. | Both the `.mkv` and the `.mp4` end up in the game folder, and the `.mp4` plays. OBS shows no remux error. | | |
| 14 | Open the settings, untick "Group clips into monthly folders", click OK, and save a replay during a game. | The clip goes straight into `<recording folder>\<Game>\`, with no month folder. | | |
| 15 | Set the clips folder to another folder (ideally on **another drive**, such as D: when OBS records to C:), click OK, and save a replay during a game. | The clip ends up in `<new folder>\<Game>\…` and is gone from the recording folder. The log has no "failed" line. | | |
| 16 | Close OBS and start it again. Open the settings. | Your changes (clips folder, monthly folders) are still there. | | |
| 17 | Add a **Window Capture** source of the game as well, or instead of Game Capture, and repeat steps 4 and 5. | The same behaviour as with Game Capture. | | |
| 18 | With the game running and the buffer started by Clip Atlas, close OBS completely, then start it again. Repeat 3 times. | OBS closes and starts cleanly every time, with no crash and no "not responding". | | |
| 19 | (Optional) With the game running, switch **Profile** in OBS's menu bar, then switch back. | Note what the Replay Buffer did; whatever it does is fine. If it stopped, Clip Atlas does not restart it until the game changes (a known limitation). | | |
| 20 | (Optional) Put a Window Capture of the game **only** in a scene that is not on air, so it shows only in Preview (Studio Mode) or not at all, then save a replay. | Note which folder it went to. | | |
| 21 | Look through the log for lines with `clip-atlas`. | Every save has an INFO line with the final path. No WARNING or ERROR lines, apart from any you caused on purpose. | | |
